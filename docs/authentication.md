# Authentication Flow

## Overview

Task Master uses a token-based authentication mechanism consisting of two types of tokens:

- Access Token
- Refresh Token

The Access Token is used to authorize protected API requests.

The Refresh Token is stored as an HttpOnly cookie and is used to generate a new Access Token when the current one expires.

```text
Login
   │
   ├── Access Token (Response Body)
   │
   └── Refresh Token (HttpOnly Cookie)
```

---

## Access Token

The Access Token:

- Is returned in the login response.
- Is stored on the client.
- Is included in the `Authorization` header.
- Has a short expiration time.
- Is removed during logout.

Example:

```http
Authorization: Bearer <access_token>
```

---

## Refresh Token

The Refresh Token:

- Is generated by the backend.
- Is stored as an HttpOnly cookie.
- Cannot be accessed by JavaScript.
- Is automatically sent by the browser.
- Has a longer expiration time.
- Is rotated every time the refresh endpoint is called.
- Is removed during logout.

The frontend never stores or reads the Refresh Token directly.

---

## Login Flow

```text
Login Form
      │
      ▼
POST /api/auth/login
      │
      ├── Access Token
      │
      └── Refresh Token (HttpOnly Cookie)
      │
      ▼
Store Access Token
      │
      ▼
Navigate to Dashboard
```
